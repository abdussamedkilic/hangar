# Hangar v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hangar v1: a single dark-themed Tauri desktop app that unifies Steam, Epic and Ubisoft games and can launch a game through a platform of the user's choice.

**Architecture:** Platform reading, merging and SQLite logic live in a Tauri-independent Rust library (`crates/hangar-core`) and are tested with fixtures. `src-tauri` is a thin layer: commands, events and opening platform links. The UI is written in React + TypeScript + Vite; the design follows the "5 · Kokpit + Vitrin" direction from the spec.

**Tech Stack:** Rust (edition 2021), Tauri 2, rusqlite (bundled), serde/serde_json, ureq, winreg (Windows only), React 18, TypeScript, Vite, Vitest, @tanstack/react-virtual, gsap, lenis.

**Spec:** `docs/superpowers/specs/2026-11-09-hangar-design.md`

## Global Constraints

- Target: Windows 11, x64; Linux/macOS are out of scope. `hangar-core` keeps Windows-specific code only under `#[cfg(windows)]` and stays buildable and testable on Linux.
- Platforms in v1: `steam`, `epic`, `ubisoft`. No GOG or EA. Epic: installed games only.
- Default launch platform is Steam; otherwise the order is `steam` → `epic` → `ubisoft`. The platform chosen per game is persistent.
- Launching/installing goes through platform links: `steam://rungameid/<appid>`, `steam://install/<appid>`, `com.epicgames.launcher://apps/<ns>%3A<itemId>%3A<appName>?action=launch&silent=true`, `uplay://launch/<id>/0`. The Epic/Ubisoft "install" button opens the respective launcher (`com.epicgames.launcher://store`, `uplay://`).
- The Steam API key is optional, stored as plain text in SQLite. No telemetry. Network is used only for the Steam Web API, Steam store search and image downloads.
- Data and cache: Tauri's `app_data_dir()` folder, i.e. `%APPDATA%\com.hangar.app\hangar.db` and `...\covers\`. I chose this instead of the spec's `%APPDATA%\Hangar` because it is Tauri's standard path.
- Code flow: a single source of truth, one GitHub repo. Claude writes, tests and pushes in a cloud workspace; the user clones it to `C:\Users\user\workdir\hangar` on Windows and updates with `git pull`.
- Visuals: dark theme only; headings in Chakra Petch, body in Figtree; background `#0f1318`, panel `#151a21`, elevation `#1d242e`, line `#252d38`, text `#e8ebf0`, muted `#8892a0`, accent `#f2a93b`, installed `#4fd18b`. `prefers-reduced-motion` is supported.
- UI copy is Turkish. Case conversion is locale-independent (`to_lowercase`, `toLowerCase`; never `toLocaleLowerCase`).
- Karpathy rules: no unrequested features, no single-use abstractions, changes limited to the task.
- Where commands run: `cargo test -p hangar-core` and `npm test` in Claude's Linux workspace; `npm run tauri dev` and `npm run tauri build` on the user's Windows machine.

## Review Focus

1. **Multiple Steam libraries / removed drive:** a path in `libraryfolders.vdf` that does not exist must not stop the scan; that library is skipped. (Task 3 test)
2. **Non-game entries:** Steam tools (`Steamworks Common Redistributables` 228980, entries named `Proton`/`Steam Linux Runtime`), Epic DLC (`addons` in `AppCategories`) and partial installs (`bIsIncompleteInstall: true`) must not enter the list. (Task 3, Task 4 tests)
3. **Invalid Steam key or offline:** installed games must still show; if owned games could not be fetched, a single-line warning appears in the UI and the app does not crash. (Task 7 test)
4. **Turkish characters:** titles and paths containing "İ/ı/ş/ğ" must not be corrupted; name normalization must give the same result under a Turkish locale. (Task 6 test, Task 9 test)
5. **Launcher not installed:** if the Epic folder or the Ubisoft registry key is missing, the provider returns an empty list rather than an error. (Task 4, Task 5 tests)

### Task 7: Database and library service

**Files:**
- Create: `crates/hangar-core/src/db.rs`, `crates/hangar-core/src/library.rs`

**Interfaces:**
- Consumes: providers, `merge::group`, model types.
- Produces:
  - `struct Db` — `Db::open(path: &Path) -> Result<Db>`, `Db::open_in_memory()`. Tables: `games(id, title, norm_title UNIQUE, cover_path, preferred, last_launched)`, `platform_entries(platform, platform_id, game_id, json, PRIMARY KEY(platform, platform_id))`, `settings(key PRIMARY KEY, value)`, `merge_overrides(a_platform, a_id, b_platform, b_id, merged)`.
  - `Db::replace_entries(groups: Vec<(String, Vec<PlatformEntry>)>) -> Result<()>` — single transaction; the `preferred`, `cover_path` and `last_launched` values of existing `games` rows are preserved; games with no remaining entries are deleted.
  - `Db::games() -> Result<Vec<Game>>` (sorted by title), `Db::set_preferred(game_id: i64, p: Platform)`, `Db::record_launch(game_id: i64, at: i64)`, `Db::set_cover(game_id: i64, path: &str)`, `Db::get_setting(k) -> Option<String>`, `Db::set_setting(k, v)`, `Db::overrides() -> Vec<Override>`, `Db::add_override(o: Override)`.

  - `fn library::resolve(game: &Game, want: Option<Platform>) -> Option<(&PlatformEntry, String /*uri*/)>` — if there is no `want`, `preferred` is used, and failing that the `Platform::ALL` order; if the entry is not installed, `install_uri` is returned.
